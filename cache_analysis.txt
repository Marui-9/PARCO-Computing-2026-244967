=== Cache Performance Analysis ===

Test 1: Small sparse matrix (2k_0p22.mtx - 1624×1624, 0.23% density)
- Threads: 8
- Iterations: 50 per configuration
- Best config: Guided+SIMD, chunk=32 (529.38x speedup)

Cache Metrics:
- L1 D-cache loads: 6,277,935,781
- L1 D-cache misses: 17,688,686 (0.28% miss rate)
- Cache references: 100,697,293
- Cache misses: 3,354,461 (3.33% miss rate)
- Total time: 0.44 seconds
- User time: 2.40 seconds (parallel execution)

Test 2: Larger dense matrix (5k_9p37.mtx - larger with 9.37% density)
- Threads: 8
- Iterations: 30 per configuration

Cache Metrics:
- L1 D-cache loads: 41,993,923,844 (6.7x more than test 1)
- L1 D-cache misses: 1,069,623,079 (2.55% miss rate - 9x worse)
- Cache references: 1,522,588,031 (15x more than test 1)
- Cache misses: 26,823,277 (1.76% miss rate - better than test 1)
- Total time: 2.34 seconds
- User time: 12.76 seconds (parallel execution)

Key Findings:
1. SIMD implementation has EXCELLENT cache performance (<3% L1 miss rate)
2. Larger/denser matrices have higher L1 miss rates but still efficient
3. Cache references scale proportionally with matrix density
4. The SIMD approach benefits from vectorized memory access patterns
5. LLC (Last Level Cache) metrics not supported on this system

Recommendations:
- Use Guided+SIMD or Static+SIMD with chunk=32 for best performance
- SIMD vectorization provides both computational AND cache efficiency
- For larger matrices, cache misses increase but remain manageable (~2-3%)
